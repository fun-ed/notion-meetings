## 下一步（依優先順序）

1. 用真實會議錄音驗證。目前的分數都來自合成語音。拿一段真實的台灣中英夾雜會議，人工對照逐字稿，確認術語、講者、【?】標示的準確度。
2. 長會議與可靠度：改由 [2026-10-21-reliability.md](2026-10-21-reliability.md) 追蹤（真實錄音測試集、長會議轉錄、系統音訊、術語校對 diff 驗證、跨段落講者比對）。
3. 抓出非術語的誤聽。例如「調到」聽成「降到」。可行方向：比對兩個轉錄模型的結果，不一致處標【?】。先用 `eval/` 量測效益再決定。
4. 錄音中途保存。MediaRecorder 每隔一段時間就把資料上傳，避免分頁當掉時遺失整場錄音。
5. 評估 Qwen-Audio-3.1-ASR（阿里雲 Model Studio，新加坡區）。它有分講者和兩級熱詞，要先確認資料政策是否能接受。依 `stt-research` skill 的流程進行。

## 之後再考慮

- **Agent 讀取 remote MCP**：magpie 會丟掉 `mcp_servers`（D-014 的實測）。有兩個方向：
  1. 模型設定改成直連 Anthropic API（官方金鑰），送出 `mcp_servers` 與 `mcp_toolset`（beta `mcp-client-2025-11-20`）。
  2. 在伺服器實作 MCP client 與工具呼叫迴圈，不依賴 gateway。

  做之前先決定可信任的 MCP 伺服器清單與工具權限。
- **接上 OpenAI 相容端點（LiteLLM 為主）與 GPT-6.1 Sol、GPT-6 Luna**：改由 [2026-10-21-llm-endpoints.md](2026-10-21-llm-endpoints.md) 追蹤。Gemini 4 之後再評估。
- **登入狀態持久化**：重新啟動不必重新登入。要對外開放時，還要補上 HTTPS、Secure cookie 與稽核紀錄（D-013）。
- **使用者自建個人 Agent**：目前只有管理員能新增 Agent。
- **資料改用 SQLite**（Node 內建 `node:sqlite`，不加套件）：會議到數千場、需要全文索引（FTS5）、或想讓登入狀態跨重啟保存時再做。
- **Claude 費用換算**：用量目前只記 tokens（走訂閱額度）；需要估算 API 費用時，加上模型價格表。
- 逐字詞同步：轉錄改要 `timestamp_granularities: ["word"]`，播放時能標到詞，而不只是整段。
- 語意搜尋：會議多、關鍵字常找不到時，再評估本機 embedding。
- 待辦事項的負責人、截止日可直接編輯；重新產生摘要時用更寬鬆的比對保留勾選（D-010 的已知限制）。

## 定期維護

- 每季，或出現新的轉錄模型時，依 `stt-research` skill 重新評測，和現行組合比較。
- 摘要模型 ID 改名時，到管理後台更新並按「測試」；轉錄模型 ID 改名時更新 `server.js`。兩者都要跑 `eval/e2e.py` 確認仍然 PASS。
